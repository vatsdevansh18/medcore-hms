# CLAUDE.md

Guidance for Claude Code sessions working on MedCore HMS.

## What this project is

A multi-tenant Hospital Management Platform, built under a strict phase-gated methodology. **Read `docs/05-DEVELOPMENT-PLAN.md` first** to find the current phase, then the specific `docs/*.md` files relevant to the work at hand. `docs/phase-reviews/PHASE-X-REVIEW.md` files record what's actually been completed and gated — treat them as more current than this file for "where are we."

**`docs/12-QUALITY-PROTOCOL.md` is mandatory reading before doing any implementation work in this repo.** It's a user-mandated, standing rule (not a suggestion) covering the implement→verify→root-cause-fix→re-verify cycle, mandatory negative/edge-case testing, continuous security review, multi-tenancy/RBAC verification requirements, "no fake completion," and the full phase-review format. A phase cannot reach PASS without going through it.

## Non-negotiable rules

- **Never start a phase's implementation without the user's explicit "START PHASE N."** Finishing a phase means writing `docs/phase-reviews/PHASE-X-REVIEW.md` (format: `docs/12-QUALITY-PROTOCOL.md` §23) and stopping — not silently continuing to the next phase.
- **The brief (`docs/source/InternMo_HMS_Brief.docx`) is the source of truth for scope.** `docs/01-PRD.md` refines it; `docs/11-DECISIONS.md` records every place scope, architecture, or the brief's own suggestions were interpreted, extended, or deviated from, with rationale. Check that file before assuming a gap is an oversight — it's probably a documented decision.
- **Tenancy isolation and RBAC are release-blocking, not "nice to have."** Any change touching a tenant-scoped model must go through the three-layer enforcement in `docs/03-ARCHITECTURE.md` §5. A cross-tenant data leak is a Critical defect that blocks the phase gate outright.
- **All requirement/security/test IDs are stable.** `FR-*`, `NFR-*`, `SEC-*` IDs defined in `docs/02-SRS.md` and `docs/09-SECURITY.md` are never renumbered — a superseded one is marked `[SUPERSEDED by ...]`, never deleted or silently reused.
- **`packages/types` is the single source of truth for API shapes.** DTOs/enums are added there first, then consumed by both apps — never duplicated ad hoc in one app.
- **Never declare a real TypeScript `enum` in `packages/types`.** Use the `as const` object + derived union-type pattern already used throughout `packages/types/src/enums.ts`. Two `enum` declarations with identical members are not mutually assignable in TS, and Prisma generates its own enum types from `schema.prisma` independent of this package — a real enum here makes every Prisma query result fail to type-check against service/DTO signatures (found in Phase 3; full reasoning in the enums.ts file header and `docs/phase-reviews/PHASE-3-REVIEW.md`).
- **A schema-changing edit to `apps/backend/prisma/schema.prisma` always needs a new migration in the same change**, not a follow-up. Reset + reseed (`prisma migrate reset --force --skip-seed && pnpm run db:seed`) is the normal way to apply it locally — there's no real data to preserve pre-launch.

## Monorepo conventions

- Package manager is **pnpm** (workspaces); do not introduce npm/yarn lockfiles.
- `@medcore/types` is consumed as compiled JS (`dist/`), not raw TS — it has a real `build` step because neither `ts-node` (backend dev) nor Next's compiler transpile arbitrary TypeScript found inside `node_modules` by default. **Any edit to `packages/types/src/*` requires `pnpm --filter=@medcore/types run build` (or a root `pnpm run build`) before the change is visible to either app** — its `dist/` is stale otherwise, and the failure mode is a confusing runtime error (e.g. `Cannot read properties of undefined (reading 'SOME_ENUM_MEMBER')`) rather than a type error, since `ts-node --transpile-only` skips type-checking.
- `packages/config` holds the shared ESLint flat-config base and TS base `tsconfig`; app-specific configs extend it rather than redefining rules. The frontend is the one exception — it uses Next's own `eslint-config-next` directly (documented in `docs/phase-reviews/PHASE-1-REVIEW.md`) since it already bundles the React/Next-specific rules our generic base doesn't cover.
- Node/pnpm versions: `package.json` `engines` states minimums (`node >=20`, `pnpm >=9`), not exact pins — the local dev machine may run newer versions. Docker images and CI pin exact versions (`node:20-alpine`, pnpm `9.15.4`) for reproducibility. Don't "fix" the `engines` field to match local `node --version`.
- Docker Compose (dev) bind-mounts each app's `src/` for hot reload but **bakes `packages/` in at image build time** — after editing `packages/types`, run `docker compose build api frontend` before `docker compose up` picks up the change.
- **`TenantContext.run()`/`.bypass()` always await the callback internally** — never change this to a bare pass-through. `AsyncLocalStorage` context reliably survives native `await` chains but not Prisma's lazy `PrismaPromise` thenable when the caller's own callback isn't `async`; wrapping the callback in an internal `async () => callback()` inside `TenantContext` itself (rather than trusting every call site to write `async () => { await ... }`) is what makes this safe regardless of caller style. Full story in `tenant-context.ts`'s doc comment and `docs/phase-reviews/PHASE-3-REVIEW.md`.
- **A cross-cutting concern that needs `AsyncLocalStorage` (or anything else) active for the _entire_ request pipeline must be a NestJS Interceptor, not a Guard.** A Guard's `canActivate()` only controls the synchronous window before the controller runs; by the time the controller executes, whatever a Guard set up has already unwound. `TenantContextInterceptor` is the reference example — the architecture doc calls this "TenantScopeGuard," but it's implemented as an interceptor for exactly this reason.
- **Watch for circular imports between a DI token's owning module and any provider that `@Inject`s that token from outside the module.** If `redis.module.ts` imports `SomeService` to register it, and `SomeService` imports the token back from `redis.module.ts`, the token can be `undefined` at evaluation time. Fix: put the token itself in a tiny standalone file (e.g. `redis.constants.ts`) that both sides import from, never re-exported through the module file.
- **Every e2e spec that boots a real Nest HTTP app (`createNestApplication()` + `app.init()`) must call `configureApp(app)` from `src/common/bootstrap/configure-app.ts`, never assemble its own subset of `main.ts`'s config.** `main.ts` and every such spec previously drifted independently, and no e2e spec ever registered the global `ValidationPipe` — meaning `whitelist`/`forbidNonWhitelisted`/`transform` were silently never exercised by any e2e test from Phase 3 through Phase 4, and query-string numbers (`page`/`limit`) arrived at services as raw strings instead of the numbers `@Type(() => Number)` is supposed to produce. Found in Phase 4; full story in `docs/phase-reviews/PHASE-4-REVIEW.md` Bugs Found #4.
- **Never bind a `PaginationQueryDto` and a second `@Query("field")` separately on the same handler.** Under the global `ValidationPipe({ forbidNonWhitelisted: true })`, NestJS validates the *whole* incoming query object against the *first* bound DTO class — any field the first DTO doesn't declare is rejected outright, even though a second `@Query()` binding for it exists on the same method. Add the extra field(s) to a DTO that `extends PaginationQueryDto` instead (see `FindDoctorsQueryDto`/`FindPatientsQueryDto`) and bind it through a single `@Query()`. Found in Phase 4; `docs/phase-reviews/PHASE-4-REVIEW.md` Bugs Found #3.
- **Any Prisma query that returns a `User` row or a relation to one (`include: { user: ... }`) in an API response must use `SAFE_USER_SELECT`** from `src/common/prisma/safe-user-select.ts`, never a bare `include: { user: true }` or an unselected `prisma.user.create/findUnique`. A bare include returns every column, including `passwordHash` — this leaked a real bcrypt hash into `POST /doctors`/`POST /patients`/`POST /users` responses in Phase 4 (`docs/phase-reviews/PHASE-4-REVIEW.md` Bugs Found #2) before being fixed at all 7 call sites.
- **Catching a Postgres `EXCLUDE USING gist` constraint violation (e.g. the appointment double-booking guard) must also catch deadlock (`40P01`), not just the exclusion violation itself (`23P01`).** Two truly concurrent inserts into the same GiST-indexed exclusion constraint can make Postgres detect a deadlock between the two transactions' index-page locks and abort the loser with `40P01`, with no `23P01` anywhere in that transaction's own error — confirmed via a direct-to-Postgres repro (25/25 truly-concurrent insert pairs raised `40P01`, never `23P01`). Both codes mean the same thing from the caller's perspective ("you lost this race, the DB is the source of truth") and should both translate to the same clean conflict response. Found in Phase 5; full story in `docs/phase-reviews/PHASE-5-REVIEW.md` Bugs Found #2.
- **A pure-ESM npm package (`"type": "module"`, e.g. `@nestjs/bullmq`/`bullmq`, or `puppeteer`/`puppeteer-core`) fails to load under `ts-jest`'s e2e config with a parse error** unless it's carved out of the default `transformIgnorePatterns` (which excludes all of `node_modules` from transformation by default). Fix is a `transformIgnorePatterns` override in the Jest config allowing `ts-jest` to transform that specific package, not a code-level workaround. See `apps/backend/test/jest-e2e.json`. Found in Phase 5 (bullmq), recurred in Phase 7 (puppeteer) — check this file first whenever a new npm package throws `SyntaxError: Unexpected token 'export'` under Jest.
- **`puppeteer`'s bundled Chromium download does not run on `node:20-alpine` (musl libc)** — same class of gap as the Prisma engine binary. Install Alpine's own `chromium` package via `apk add` and point Puppeteer at it with `PUPPETEER_EXECUTABLE_PATH=/usr/bin/chromium-browser` + `PUPPETEER_SKIP_DOWNLOAD=true` set *before* `pnpm install` runs in the Dockerfile, so the image never wastes a download it can't use. Native dev is unaffected (those `ENV` vars are Dockerfile-only). See `docs/11-DECISIONS.md` D-016, `infrastructure/docker/Dockerfile.backend`. Found in Phase 7.
- **`prisma migrate dev` refuses to run at all in a non-interactive shell** (Claude Code's Bash tool included) the moment it needs to show any confirmation prompt — e.g. adding a `@unique` constraint, even to an empty table — failing with "Prisma Migrate has detected that the environment is non-interactive." `--create-only` does **not** avoid this; the prompt-detection happens before that flag matters. When this happens: hand-write the migration's `migration.sql` (match the exact naming Prisma already uses elsewhere in `prisma/migrations/*/migration.sql` — `<Table>_<column>_key`/`<Table>_<column>_fkey`, `ON DELETE SET NULL` for an optional relation vs. `RESTRICT` for a required one), then apply it non-interactively with `prisma migrate deploy` (this command never prompts), then `prisma generate`. Found in Phase 7.
- **`@aws-sdk/client-s3`'s default `requestChecksumCalculation` ("WHEN_SUPPORTED") signs an `x-amz-checksum-crc32` requirement into every presigned `PutObjectCommand` URL it issues, but a presigned URL's body is uploaded later by a client the SDK never sees — nothing ever computes/sends that checksum, so every presigned upload is rejected** (confirmed against LocalStack: `"Value for x-amz-checksum-crc32 header is invalid"`; real AWS S3 has the same requirement, so this isn't LocalStack-specific). Fix: construct the `S3Client` with `requestChecksumCalculation: "WHEN_REQUIRED"` — see `src/common/storage/s3.service.ts`. Found in Phase 6.
- **A local S3-compatible endpoint (LocalStack, `docker-compose.yml`'s `localstack` service) is required for both native dev and e2e tests that touch attachments** — `docs/11-DECISIONS.md` D-015. Bring it up with `docker compose up -d localstack` before running EMR e2e specs; `S3Service.onModuleInit` self-provisions the dev bucket against it automatically, but only when `S3_ENDPOINT` is set (never against real AWS).
- **`$queryRaw`/`$executeRaw` bypass the tenant-scoping Prisma extension entirely** (it only hooks model operations). Every raw query touching a tenant-scoped table must bind `"hospitalId" = ${hospitalId}` explicitly, taken from the caller's JWT via TenantContext and never from request input. Always use the tagged-template form (parameterised), never `$queryRawUnsafe` with interpolated strings. See `StockService.lockMedicines` and `MedicinesService.findLowStock`. Found while building Phase 9's row locks.
- **Any write that changes a medicine's available stock or its `reorderLevel` must run inside a `$transaction` that first calls `StockService.lockMedicines` (a `SELECT ... FOR UPDATE` on the `Medicine` rows) and then `StockService.evaluateLowStock`.** The per-medicine lock is what stops concurrent dispenses overselling a batch; it was verified by removing it, which made the concurrent-dispense e2e test fail. `evaluateLowStock` maintains the FR-PHARM-004 once-per-crossing latch (`docs/11-DECISIONS.md` D-022), and skipping it silently loses alerts. Lock order is prescription row first, then medicines sorted by id, to stay deadlock-free. Found in Phase 9.
- **Never use `Prisma.Decimal`'s `isPositive()`/`isNegative()` for money checks: decimal.js counts zero as positive (`new Decimal(0).isPositive() === true`).** Use `.gt(0)`/`.lt(0)`. This shipped in Phase 10's first cut and made every freshly finalized, unpaid invoice `PARTIALLY_PAID` (and would have allowed a zero-amount checkout). The e2e status assertions caught it. `docs/phase-reviews/PHASE-10-REVIEW.md` Bugs Found #1.
- **Every invoice line, automatic or manual, goes through `ChargesService`** (`src/billing/charges.service.ts`), inside the same `$transaction` as the clinical write it bills for. Never write `InvoiceItem`/`Invoice.total` directly. The database enforces `lineTotal = quantity × unitPrice`, `subtotal = SUM(lineTotal)` (a deferred trigger at commit), and the immutability of non-DRAFT lines (migration `20260924120000_billing_integrity`, D-028), so a direct write fails at commit. Billing lock order: Appointment row → Invoice row, after any clinical locks (dispense: Prescription → Medicines → Appointment → Invoice).
- **An e2e spec that creates encounters, lab orders, or dispenses must call `purgeBilling(prisma, hospitalIds)` (`test/helpers/billing-cleanup.ts`) before deleting appointments in `afterAll`.** Those actions create invoices automatically (RESTRICT FK to Appointment), and the billing triggers block naive deletes of finalized lines.
- **Env values a spec needs must be set in a helper module imported *before* `AppModule`** (see `test/helpers/payment-test-env.ts`), not in `beforeAll`. `ConfigModule.forRoot({ validate })` snapshots `process.env` when `app.module.ts` is first imported, and `ConfigService.get` reads that snapshot.
- **Every notification goes through `NotificationsService.record(tx, event)` inside the triggering transaction, followed by `notifications.publish()` after commit.** Never write `Notification` rows directly, and never pick channels in a producer; the trigger table (`src/notifications/notification-triggers.ts`, brief §7.8) decides them. Give every event a stable `dedupeKey` (the entity id, plus a window or crossing time where the same entity can legitimately notify again). A forgotten `publish()` isn't a lost message (the 30s outbox sweep delivers it) but it adds up to 30s of latency. `docs/11-DECISIONS.md` D-032.
- **Never filter "just committed" rows by comparing a DB-generated timestamp with the Node process clock.** The outbox drain's `createdAt <= Date.now()` silently skipped fresh rows whenever the Postgres container's clock ran a few ms ahead (an intermittent Phase 11 e2e failure). Age guards are only acceptable where they're coarse (the sweep's 10s). `docs/phase-reviews/PHASE-11-REVIEW.md` Bugs Found #1.
- **Map rows to client payloads field by field (`toView`), never by spreading a Prisma row.** Callers pass wider rows than you expect; the in-app worker's row included the recipient's email/phone, the dedupe key, and the hospital id, and a `...row` spread pushed them all over Socket.IO (caught by the Phase 11 payload-shape test before shipping).
- **Nest runs `dispose()` (which closes the Socket.IO server and its Redis adapter) *before* `onApplicationShutdown` (where `@nestjs/bullmq` closes workers).** Any worker whose job touches the socket server must close itself in `beforeApplicationShutdown` (see `ChannelProcessor`), or an in-flight job hits a closed Redis connection as an unhandled rejection. Found in Phase 11 e2e teardown.
- **With `plainToInstance(..., { enableImplicitConversion: true })` (env validation), `@Transform` receives the *already converted* value**, so `Boolean("false")` arrives as `true`. Parse booleans from `obj[key]` instead. The request `ValidationPipe` doesn't enable implicit conversion, so DTO transforms there still see the raw string.
- **The e2e suite runs in one Jest worker (`"maxWorkers": 1`).** Every spec process runs outbox dispatchers and channel workers against the shared Redis/Postgres, so parallel specs steal each other's notification jobs and deliver them through the wrong (unfaked) senders. `docs/11-DECISIONS.md` D-034. An e2e spec that needs to control delivery overrides `EMAIL_SENDER`/`SMS_SENDER` (the network hop only), never the dispatcher or workers.
- **Doctor schedules are wall-clock times in `Hospital.timezone`; appointments are UTC instants.** Convert with `src/common/time/zoned-time.ts` (`zonedWallTimeToUtc`, `localDateKey`), never `new Date(\`${date}T${hh}:00Z\`)`. Until Phase 12 every schedule was read as UTC, so a 09:00 IST doctor got 14:30 slots. `docs/11-DECISIONS.md` D-037. A spec that asserts UTC slot times must pin its test hospital to `timezone: "UTC"` (see `appointments.e2e-spec.ts`).
- **No API response may contain an S3 storage key** (`signatureImageUrl`, `pdfUrl`, `storageKey`, `reportFileUrl`, `receiptUrl`). Map to a flag (`hasSignature`, `pdfReady`) and serve files only through pre-signed URLs. Use `S3Service.getDownloadUrl`/`getUploadUrl` for anything a browser opens, and `getInternalDownloadUrl` only for URLs the server fetches itself (e.g. Chromium rendering a PDF). In Docker dev those are different hosts (`localhost:4566` vs `localstack:4566`, via `S3_PUBLIC_ENDPOINT`); signing a browser URL with the internal client broke every download in the compose stack from Phase 6 until Phase 12. D-036.
- **Patient-facing doctor data is name and specialization only.** Don't use `SAFE_USER_SELECT` for a doctor a patient will see; it includes email and phone. D-036.
- **The web app must refresh the access token only through `refreshAccessToken()`** in `apps/frontend/src/lib/api-client.ts` (one refresh per tab, Web Lock across tabs). A second, parallel refresh with the same cookie is a replayed rotated token, and the backend revokes every session for that user (SEC-AUTHN-004).
- **Next.js page files (`app/**/page.tsx`) may only export the page component and Next's reserved names.** Put helpers in `lib/` (e.g. `lib/appointment-rules.ts`), or the production build fails.
- **Form fields reserve the line under the input (`FormField`), and forms re-validate on change after a submit attempt.** An error line appearing on blur pushed the Submit button away mid-click and the click was lost (caught by the Playwright registration journey). D-038.
- **Playwright against Next.js:** Next renders an empty `role="alert"` route announcer, so select the app's alerts with `[role="alert"]:not(#__next-route-announcer__)`. Headless Chromium downloads PDFs instead of showing them, which aborts the tab's navigation; capture the pre-signed request (`popup.waitForRequest(/X-Amz-Signature=/)`) instead of waiting for the URL.
- **Stop any running API (the `api` container or a native `pnpm run dev`) before the backend e2e suite.** Its outbox dispatcher and workers take the specs' notification jobs (D-034). A native `nest start --watch` also restarts whenever a watched file changes, so edit then wait for "Nest application successfully started" before running the browser suite.
- **The browser E2E suite (`apps/frontend/e2e`, `pnpm --filter @medcore/frontend exec playwright test`) needs a running stack** (API :3001 with Postgres/Redis/LocalStack, web :3000; native or Docker). Global setup runs `apps/backend/scripts/e2e-portal-fixture.ts` and builds the patient's history through the real API; teardown deletes it (`E2E_KEEP_FIXTURE=1` keeps it for debugging). Clear the auth throttle keys in Redis between repeated runs.
- **Analytics days are the hospital's calendar days, grouped in SQL** with `to_char((col AT TIME ZONE 'UTC') AT TIME ZONE ${tz}, 'YYYY-MM-DD')` and bound instants as `(${iso}::timestamptz AT TIME ZONE 'UTC')`. See `AnalyticsService.localDay`/`instant`. Test with a non-UTC hospital and rows near local midnight, dated in a year no other data uses (the analytics spec uses March 2019 so the platform-wide numbers stay exact). `docs/11-DECISIONS.md` D-040.
- **List filters that need several statuses use `@CommaSeparatedEnum(values)`** (`src/common/validation/comma-separated-enum.decorator.ts`, `?status=FINALIZED,PARTIALLY_PAID`) and the service uses `{ in: query.status }`. A single value still works, so existing callers are unaffected.
- **A filter on a role-scoped list narrows within the caller's scope, never replaces it.** A doctor asking `GET /appointments?doctorId=<colleague>` gets nothing, not their own list (found in Phase 13: the own-scope assignment silently discarded the filter).
- **Demo data:** `pnpm run db:seed` (master data) then `pnpm run db:seed:history` (two weeks of visits, bills, and lab work; idempotent per hospital). History rows must obey the same rules the services and DB triggers enforce; `prisma/seed-history.ts` is the reference.
- **Stopping a background `pnpm run dev` shell can leave its Node child listening on :3000/:3001.** A leftover API process runs outbox dispatchers and workers that take the e2e specs' notification jobs (Phase 13's first full run failed 9 notification tests this way). Before the backend suite, check `Get-NetTCPConnection -LocalPort 3000,3001 -State Listen` and stop any leftover `node` process you started. The frontend package has no `dotenv-cli`; start it with plain `pnpm run dev` (its API URL default matches).
- **The e2e suite clears the auth rate limiter (`throttle:*` in Redis) before every spec file** (`test/helpers/reset-rate-limits.ts`, via `setupFilesAfterEnv`). Auth routes allow 100 requests per 15 minutes per route and client, and every serial spec shares one loopback IP; in Phase 13B the suite crossed 100 logins and every later spec failed with 429. Don't rely on a shared budget within a file either: a spec that logs in more than ~90 times needs its own file. Limiter behaviour itself is tested only in `test/rate-limit.e2e-spec.ts`. D-041.
- **Playwright `getByLabel("Doctor")` also matches the global search box** (its label is "Search patients, doctors, and medicines"). In the staff workspace, pass `{ exact: true }` for any label that's a substring of that, and prefer `[data-status="…"]` over `getByText` for status badges ("Paid" is also a summary label on the bill).
- **A staff screen reached from a list (not the sidebar) must be added to `WORKFLOW_ACCESS` in `components/modules/staff-nav.ts`** and wrapped in `<RoleGate route="/dashboard/<x>/:id">`, with the roles of the API calls it makes. Button visibility comes from pure helpers that copy API rules (`lib/appointment-actions.ts` copies `ALLOWED_TRANSITIONS` in `appointments.service.ts`); change both together. These are UX only; the API is the control. D-041.

- **A browser upload to a pre-signed S3 URL needs a bucket CORS rule for the web origin, and Node-side tests can't catch its absence** (Node doesn't enforce CORS). `S3Service.onModuleInit` applies the rule to the LocalStack bucket from `CORS_ORIGIN`; a production bucket must get the same rule from infrastructure. Test uploads in the browser (Playwright), not only through supertest. Every browser upload was broken from Phase 6 until the Phase 13B follow-up. D-042.
- **Playwright fixtures must not change seeded data other tests depend on.** A test that edits a doctor's hours or signature uses the run's own e2e doctor (`fx.ownDoctorId`). A test that needs "a doctor" names the seeded one (`fx.doctorId`), never `.first()` of a list that other fixtures can grow. To capture a popup's pre-signed download, listen on `page.context()` before clicking, not on the popup: fast links fire before a popup listener attaches.

- **Colour tokens must pass `src/lib/contrast.test.ts`** (WCAG AA in both themes, and the two dark blocks in `globals.css` must match). Change a token and run it. Use the `-foreground` token for text on a solid tone (`text-danger-foreground`), never `text-white`, which fails in the dark theme. D-043.
- **A dialog opened from state (no `Dialog.Trigger`) must pass `onCloseAutoFocus={useReturnFocus(open)}`** (`hooks/use-return-focus.ts`), or focus falls to the top of the page when it closes. All seven current dialogs do. `e2e/accessibility.spec.ts` checks one, and the axe scan runs every screen in both themes; add new screens to it. D-043.
- **No animation library:** motion is CSS keyframes in `globals.css`, which the global reduced-motion rule disables. framer-motion was removed in Phase 14 (a 40 kB chunk for two effects). D-043.

- **Run the full Playwright suite against production builds, not dev servers:** `docker run -p 3000:3000 -e HOSTNAME=0.0.0.0 medcore-hms-frontend-prod` for the web app (build it with `docker build -f infrastructure/docker/Dockerfile.frontend --target runtime -t medcore-hms-frontend-prod .`), and `pnpm run build` then `pnpm exec dotenv -e ../../.env -- node dist/main.js` in `apps/backend` for the API. On this machine the dev servers produce false failures: Next compiles routes on demand in 10–15 s under memory pressure, and `nest start --watch` restarts when the e2e fixture script runs in the backend folder. Every browser test resets the rate limiter (`resetRateLimits`); keep that `beforeEach` in new spec files. Never use a bare `isVisible()` to branch: it doesn't wait. D-043.

- **A custom Jest `--config <path>.json` file's `rootDir: "."` resolves relative to *the config file's own directory*, not the CWD it's invoked from.** `apps/backend/test/jest-e2e.json` living in `test/` means its `rootDir` is actually `apps/backend/test/`, not `apps/backend/` — invisible for running tests (they live right there) but fatal for `collectCoverageFrom`: Jest's coverage file-crawler only walks `roots` (default `[rootDir]`), so a pattern reaching outside it (`../src/**/*.ts`) matches zero files no matter how the glob is written, silently printing `Unknown% (0/0)` with no error. Setting `roots` to include the external directory does **not** fix it either (confirmed empirically). The fix is `apps/backend/jest-e2e.coverage.json`, living at the backend root so its own `rootDir: "."` is `apps/backend/` — same `testRegex`/`setupFilesAfterEnv` pointed at `test/`, `collectCoverageFrom: ["src/**/*.ts"]` resolving correctly. Run with `pnpm run test:e2e:coverage`. Found in Phase 15 (worked around by arguing coverage differently, D-044), actually root-caused in Phase 17 once the brief's literal "Jest coverage HTML report" deliverable required a real number: e2e coverage is 92%+ statements/lines, comfortably clearing the brief's 70% bar, vindicating D-044's claim that business logic is thoroughly tested — just via integration tests, which mocked-unit coverage structurally can't see.
